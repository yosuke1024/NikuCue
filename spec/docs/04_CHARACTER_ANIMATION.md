# 04. キャラクター設定 / アニメーション仕様

## 1. キャラクターバイブル

仮名: **Mali / มะลิ / マリ**。性別は固定しない。ユーザーが呼び名を変更できるが、性格は変えない。

丸いクリーム色の猫。薄いキャラメル色の耳としっぽ先、白い口元、小さなピンクの鼻。丸い頬、短い足、先が少し曲がる太いしっぽ。頭はやや大きいが、猫らしい耳・足・尾の付け根が分かる。アクセサリーは初期版なし。

性格はおだやかで、少し甘えん坊。得意なのは「待つ」「一緒に喜ぶ」「休むのを認める」。命令する先生ではない。長い人生訓も、幼児語の連打も不要。語尾に毎回にゃんを付けない。タイ語で不自然な性別付き一人称・敬語を強制しない。

視線は通常ユーザーへ、習慣達成で一瞬チェック方向へ、最後はユーザーへ戻す。猫を広告へ向けたり、広告を指ささせたりしない。

既存のPawse・Finch・他IPの猫の輪郭、配色配置、衣装、名前、音を再利用しない。商用利用可能な独自素材だけを採用する。

## 2. 作り方

初期方式は**2Dパーツアニメーション**。SpriteKitの親子ノードで頭・耳・体・前足・尾・顔を動かす。画像やシェイプを扱える2Dフレームワークなので、この方式を選ぶ。[S01]

最初はCore Graphics/CGPathで描いたオリジナル形状をテクスチャ化して使う。毎フレームパスを生成しない。絵を差し替える時は同じnode IDとpivotを保ち、`CharacterArtProvider`を差し替える。

画像生成した1枚絵は、いきなりアニメ素材にはならない。採用する場合も背景除去、パーツ分け、隠れた部分の描き足し、表情差分、接続部とpivotの確認が別途必要。作業を実施していない段階で完了扱いしない。

Rive/Spine/Live2D/3D/有料マーケット素材を必須にしない。動画生成を再生して反応アプリに見せる方式にも逃げない。

## 3. アート契約

`assets-spec/character_spec.json`を正本にする。基準キャンバス1024×1024、透明背景、座位の地面Yは180（SpriteKit座標で下から）。カメラ固定・正面に近い視点。キャラクター本体は約760×720以内。

親子ノード:

```text
root
 ├ shadow
 └ bodyPivot
    ├ tailPivot → tail
    ├ body
    ├ hindPawL / hindPawR
    ├ forePawLPivot → forePawL
    ├ forePawRPivot → forePawR
    └ headPivot
       ├ earLPivot → earL
       ├ earRPivot → earR
       ├ head
       └ face（eyes/mouth/nose/cheeks）
```

耳が頭の後ろに、前足が胴の前に自然に見えるz-orderを固定。親ノード変更で継ぎ目が見えないよう隠れ部分を10〜15%重ねる。しっぽの回転中心を真ん中にせず付け根に置く。

顔はneutral / softSmile / closedHappy / curious / sleepyの5差分。口・目の位置を変えず、表情だけを切り替える。悲しみ/涙/空腹はv1の素材に含めない。

パーツ成果物がPNGならsRGB/RGBA、透過、基準キャンバス/pivotメタデータつき。書き出し元を保存し、完成画像だけを渡して編集不能にしない。ライセンスと制作方法はasset inventoryに記録する。外部フォントを同梱する必要はない。

## 4. 動作クリップ

数値は試作開始用。実機で可愛さと気持ち悪さを評価し、±20%程度の調整は記録して行ってよい。

| ID | 動作 | 長さ / 主要な動き |
|---|---|---|
| idle | 待機 | 呼吸3.6秒。胴の縦scale±1%。瞬き4〜7秒ごと。尾±5度 |
| greet | おかえり | 1.1秒。顔を上げて右前足を小さく2回振る |
| pet | なでられる | 0.9秒。目を細め、頭を7度傾けて少し頬を寄せる |
| celebrate | できた | 1.6秒。予備動作→小さく跳ぶ→着地→嬉しい顔 |
| cheer | 応援 | 1.2秒。身を少し起こし、両前足を胸の前へ。煽らない |
| settle | 休んでも大丈夫 | 1.3秒。ゆっくり瞬き、肩を下ろし、落ち着く |
| doze | うとうと | 呼吸4.8秒。顔を少し下げ、半眼。タップ/達成にはすぐ反応 |
| milestone | 特別なお祝い | 2.2秒。小さな2段階の喜び+最大3つのハート。全画面演出なし |

### celebrateのタイミング

0–140ms: 胴scaleX=1.03 / scaleY=0.96。頭は遅れて少し沈む。
140–420ms: bodyPivot以下を基準キャンバスでY+34、胴scaleY=1.025へ。前足を少し上げる。
420–680ms: 着地。bodyPivotの移動差分Y=0、胴scaleX=1.035 / scaleY=0.96。
680–1,050ms: 中立のscaleへ戻し、head+5度、closedHappy。
1,050–1,600ms: 尾を小さく揺らしてsoftSmile、idleへblend。

画面の40pxジャンプとキャンバスの40unitを混同しない。演出は1024unit基準で、表示倍率に応じて縮む。影はY移動せず小さく薄くする。地面を突き抜けない。

## 5. アニメ制御

全ノードの基準transformを保持し、クリップ終了/中断で必ず正規化する。キー付きSKActionを使い、同じキーの無限actionを増殖させない。

idleの呼吸と主動作が同じscaleを同時変更しない。主動作中は対応idle actionを停止し、終了時に復元。表情の切替は80〜120ms程度のblend。毎回猫のSceneを作り直さない。

画面離脱、アプリinactive/background、購入/同意sheet表示中はsceneをpause。復帰時に古い反応を高速再生しない。1アプリ1つのvisible cat scene。最大30fpsを標準に実機計測し、必要以上の常時60fpsは狙わない。低電力モードではidleの頻度を落とす。

## 6. 承認基準

静止画: 64px相当でも猫と分かる。耳/前足/尾が左右で不自然に増減しない。表情差分で別の猫にならない。
動き: 目と口が顔から滑らない。継ぎ目が裂けない。呼吸が膨張/収縮する風船に見えない。跳躍で足の本数が変わらない。変形が極端でない。
感情: neutral / glad / sleepyを説明なしで区別できる。休みの反応が罰に見えない。3回連続で見ても煩わしくない。
アクセシビリティ: Reduce Motion、無音、触覚OFFでも達成が分かる。

Claude Codeは「動く」まで実装できても「可愛い」の最終判定者ではない。Yohと最初の利用者の実機確認をG1として残す。G1未完でもロジック実装は進めてよいが、App Store公開ゲートを通さない。
