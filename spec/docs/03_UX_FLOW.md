# 03. 画面遷移 / UI仕様

## 1. ナビゲーション

下部タブバーは置かない。操作の多い下部ナビとバナーで画面を挟まない設計にする。[S10]

```text
起動 → ローカルDB読込 → 初回ならオンボーディング → Home
                                               ├→ 習慣追加/編集（sheet）
                                               ├→ 履歴（月）→ 日別内訳/訂正
                                               └→ 設定
                                                    ├→ 通知
                                                    ├→ 広告削除（購入sheet）
                                                    ├→ バックアップ/復元
                                                    ├→ プライバシー/広告設定
                                                    └→ ヘルプ/全データ削除
通知をタップ → DB準備完了後Home（過去の習慣の達成扱いにしない）
```

起動時に広告・商品情報の取得を待たない。購入状態が不明なら広告なしでHomeを描画し、並行して権利確認する。

## 2. Home

| 領域 | 内容 / 操作 |
|---|---|
| 上部 | 今日の日付。履歴/設定へのボタン。44pt以上のタップ領域 |
| 猫の部屋 | 約220ptを基準に可変。猫・影・小さな座布団。猫へのタップ |
| 吹き出し | SwiftUIのTextで描画。SpriteKit内に文字を焼き込まない |
| 今日の習慣 | 各行にアイコン、名前、チェック、補助メニュー。行全体を誤ってdoneにしない |
| 進捗 | `2/3できた · 1つは休み`のように状態を分離 |
| 追加 | 習慣一覧の末尾。5件時は上限説明 |
| バナー | Home最下部の固定専用領域。コンテンツ/ボタンと非操作余白で分離 |

全体はスクロール対応。小画面・Dynamic Typeでは猫の高さを160ptまで抑え、習慣と操作を優先。猫を残すために本文を極小にしない。画面上で一覧と広告が重ならない。

チェックは常時有効。お祝いアニメーション中も入力を塞がない。画面中央に全画面の達成ダイアログは出さず、猫の動きと短い吹き出しで返す。

## 3. 習慣編集sheet

上: キャンセル / タイトル / 保存。
名前、5カテゴリ、毎日/曜日、アーカイブ。対象曜日ゼロ・空名は保存不可。キーボードで保存/キャンセルを隠さない。カテゴリはアイコンだけでなくラベルを付ける。

「曜日の変更は明日から反映」を編集時に常に表示。今日のためだけに予定を改変する導線は作らない。

## 4. 履歴

月のカレンダー。doneのある日、休みのみ、未記録、予定なしを形/ラベルでも区別する。色だけに依存しない。日付タップで日別内訳。編集可能期間外は読取専用。過去の未記録を赤い失敗マークで埋め尽くさない。

上部に「一緒にできた日 N日」。連続記録の切断やランキングはない。

## 5. 設定/購入

広告削除は設定に常設するが、起動時や未達時に販売ポップアップを出さない。購入画面には「買い切り」「猫と習慣の機能は無料版と同じ」「購入を復元」を示す。実際の価格はStoreKitから取得する。[S06]

不適切な広告の報告はヘルプから開けるようにする。スクリーンショット添付は本人の任意。習慣名や履歴を自動添付しない。[S08]

## 6. エラーと空状態

| 状況 | 表示と挙動 |
|---|---|
| 予定なし | 猫は通常通り。追加CTAまたは次の予定日。達成0扱いで責めない |
| 保存失敗 | 保存できなかったと明示。チェックは元に戻す。喜ばせない |
| 広告取得失敗 | エラーメッセージを出さず、操作可能。コントロールを動かさない |
| 購入情報取得失敗 | 価格欄は再読み込み。架空の固定価格を代用しない |
| 通知拒否 | アプリは普通に利用。設定へ行く説明を一度表示 |
| 復元データ不正 | 元データを保持して理由表示。自動的に修復して捨てない |
| DB初期化失敗 | DBを削除しない。再試行/サポート。読み出せるなら安全な診断だけ |

## 7. 視覚・操作基準（この製品の設計値）

温かい背景、十分な文字コントラスト、強い赤の不達成表示なし。本文はシステムフォント17pt相当を基準にDynamic Typeへ追従。タイ語の上下の記号を切らない。色や形だけに状態を任せない。タップ領域は44×44pt以上を目標。

Reduce Motionでは跳躍・大きな揺れ・粒子を止め、表情変更+短いフェードを使う。猫の状態をVoiceOverで意味として伝える。アプリ独自の「動きを減らす」はOS設定とのORで有効。触覚なしでも全情報が分かる。

右手/左手、片手、小画面で「できた」の代わりに広告を押しやすくないか実機確認する。余白の数値を満たせば審査上安全、とは判断しない。
