# 01. プロダクト企画 / MVP

## 1. コンセプト

**NikuCue**（採用名。商標・ストア登録可否は公開前に確認）。猫のMaliが小さな生活習慣を見守り、記録した達成を一緒に喜ぶiPhoneアプリ。

日本語の中心コピー: **小さな「できた」を、猫といっしょに。**
英語: **Small wins, with a little cat.**
タイ語の意味: 小さな良い習慣を、一緒に喜んでくれる猫と続ける。

名称の「Cue」は行動の合図を意味する。肉球を連想させる「Niku」と組み合わせ、猫が習慣のきっかけをくれるブランドとする。英語話者・タイ語話者に「Niku」だけで肉球が伝わるとは前提にしない。Appアイコンは文字ではなく肉球で伝える。

これはキャラクターを添えた汎用タスク管理ではなく、「行動を記録したときの嬉しい反応」を価値の中心に置く。習慣の効果や継続率が改善することは未検証の仮説。治療・健康効果・依存防止効果を断定しない。

## 2. 最初の利用者と市場

最初の利用者は猫好きのタイ人のパートナー。iPhoneでタイ語を自然に読めることを優先する。個人向けの贈り物として喜ばれることと、一般利用者が継続して使うことは別々に評価する。

公開時の対象は、猫が好きで、厳しい目標管理より優しいきっかけを求める成人を中心とした一般利用者。子ども向けゲームとして設計・宣伝しない。ただし年齢評価や広告の適切性は実際の内容・SDK・配信地域で審査する。[S08]

## 3. 体験の一巡

自分で選んだ習慣を実行 → アプリで「できた」 → 保存 → 猫が目を細めて嬉しそうに反応 → 今日の記録が残る。

通知は猫に会うきっかけ。通知そのものがOS上を歩く猫になるわけではない。猫が動くのはアプリ内。アプリ外の表示は通常のローカル通知だけにする。[S04]

## 4. MVPの固定スコープ

| 機能 | v1の決定 |
|---|---|
| キャラ | 1匹。呼び名だけ変更可能。毛色・性格選択はなし |
| 空間 | 1つの簡素な部屋。朝/昼/夜の色変化だけ |
| 習慣 | 有効なもの最大5件。1日1チェック。毎日または曜日指定 |
| 記録 | できた / 今日は休む / 未記録。今日と直近7日を修正できる |
| 反応 | 待機・歓迎・なでる・喜ぶ・くつろぐ・応援・うとうと・特別なお祝い |
| 成長の代わり | 「一緒にできた日」累計。3/7/14日の節目で特別な反応。連続日数ではない |
| 通知 | 全体で最大2枠。曜日と時刻を選択。習慣別の通知はなし |
| 履歴 | 月カレンダー + 日別内訳。過去7日の訂正 |
| 言語 | th / en / ja。システム設定優先、アプリ内切替も可能 |
| 保存 | SwiftDataをローカルのみで利用。手動JSONバックアップと復元 |
| 収益 | Homeのバナー1枠。買い切り広告削除。機能差なし |
| 音 | 初期版は無音が基準。触覚ON/OFF。音素材は必須にしない |

5件の上限はMVPの品質・画面設計上の上限であり、課金誘導ではない。有効件数を減らせば追加できる。公開説明に上限を明記する。

## 5. 初期版で作らないもの

Android、iPad最適化、Web版、ログイン、端末間同期、ウィジェット、Live Activities、Apple Watch、HealthKit、歩数自動取得、チャット、AI会話、キャラの空腹/寿命、通貨、着せ替えショップ、家の模様替え、複数ペット、競争ランキング、友達機能、週n回/数量目標、習慣別リマインダー、広告視聴報酬。

外す理由は「作れない」ではなく、最初の相棒体験を評価する前に制作・運用範囲を増やさないため。

## 6. 成功基準（検証用の仮置き）

個人テストでは、説明なしで習慣を1つ作って達成を記録できること、タイ語に違和感がないこと、猫への反応が「邪魔」より「嬉しい」に寄ることを見る。7日間の試用で、少なくとも別々の3日に本人が自発的に使ったかを確認する。これは市場PMFの基準ではない。

公開判断前には知人以外を含む5〜10人程度でも試す。まず通知を切った理由、記録をやめた理由、猫の好き/嫌いを聞く。インストール数だけで評価しない。

解析用の独自バックエンドは作らない。試用者が明示的に共有する診断データと聞き取りで評価する。集計規模が小さい間は改善幅を因果効果として語らない。

## 7. プロダクトの姿勢

達成した日は喜ぶ。休む日は休ませる。戻った日は歓迎する。課金しても猫の愛情は変わらない。広告の視聴・クリックで猫が喜ぶこともない。

本体・素材・通知がオフラインで動くことと、広告/購入の通信は区別して説明する。維持費ゼロは自前インフラ/API原価についての設計目標であり、登録費・手数料・保守作業は残る。
